# PoC 3 Evaluation: Beat / Downbeat Analysis and Bar Mapping

- **Date**: 2026-10-04
- **Spec**: [specs/003-beat-bar-mapping/spec.md](../../specs/003-beat-bar-mapping/spec.md)
- **Status**: **Draft** — Go/No-Go の Human Review 待ち。打撃の割り当て (SC-004) と叩いた正解のブレ (SC-005 の後半) は、手で拍を付ける作業を見送ったため未測定。

## 結論 (案)

**条件付き Go** — 拍・小節の頭・BPM・拍子の推定は、評価セット 5 曲で目標を満たした。PoC 3 の技術仮説 (「打撃イベントを曲の小節・拍の上に並べられる」) は、小節単位の練習区間の切り出しに必要な精度で成立している。

条件は次の 2 つ。

1. 打撃の 16 分・3 連符の位置まで正しく割り当てられるか (SC-004) は、まだ測れていない。ユーザー演奏との比較を設計する段階で、必要な精度を決めてから測る。
2. 曲の入りなど推定が不安定な区間がある (PLASTIC BOMB の 0:10〜0:30)。練習区間の切り出しでは、推定の信頼度を出して扱う必要がある。

(拍 F は整理の有無で変わらない。位置合わせなしの値。最大メモリは 0.8〜1.0 GB)

- **小節の頭の整理 (Viterbi) が効いた**: WORKING MAN の 1:10〜1:58 では、推定が本当の小節の頭に加えて 4 拍目にも高い値を出していた (PoC 2 で「2 拍ずれ」に見えたもの)。整理後は 1 拍目が一貫して選ばれ、0.895 → 0.996。PLASTIC BOMB も 0.627 → 0.850。他の曲は悪化しない。開発者が `check.wav` を聴いて「合っている」と確認した (research R-12)。
- **BPM**: 推定の拍は 20 ms 刻みのため、1 拍の間隔の中央値では 187 BPM 付近で 2% 近くずれた (PLASTIC BOMB 187.5 vs 190.7)。8 拍分の間隔から求めるように直し、最大 0.67% になった。PLASTIC BOMB の残りの 0.67% は、正解側の BPM を叩いた拍の間隔の中央値で求めているため (直線を当てはめると推定 190.56 / 正解 190.69)。
- **PLASTIC BOMB の弱点**: 0:10〜0:30 (ドラムが入ってから 20 秒) だけ、推定した拍が叩いた拍より 46〜82 ms 遅れ、小節の頭もずれていた。0:30 以降は ±25 ms 以内。曲の入りで推定が拍を見失っている。

## 原曲と Drum Stem の比較 (US4)

| 入力 | 拍 F | 小節の頭 F | 打撃の割り当て (叩いた正解) |
|---|---|---|---|
| 原曲 | 0.953 | 0.939 | 0.786 |
| Drum Stem | 0.905 | 0.825 | 0.612 |

原曲の方がはっきり良い (特に ONLY YOU: Drum Stem では拍 F 0.748)。計画どおり、ベースやコード進行が小節の頭の手がかりになっている。拍の推定は原曲で行う。
ユーザーの演奏 (ドラムだけの音) に同じ推定を使うのは精度が落ちるため、演奏側は Reference の BeatGrid を共有する設計にする。

## 位置合わせ (ドラムへの補正) について

| 曲 | 叩いた拍 − 推定 (位置合わせなし) | 位置合わせ後 |
|---|---|---|
| NO. NEW YORK | −3 ms | −13 ms |
| B・BLUE | +4 ms | −6 ms |
| ONLY YOU | −2 ms | −21 ms |
| WORKING MAN | +4 ms | −16 ms |
| PLASTIC BOMB | −7 ms | −25 ms |

開発者が叩いた拍は、推定そのままの拍とほぼ一致する (±7 ms)。ADTOF の打撃 (原曲のドラム) は、そこから 10〜20 ms 早い。
位置合わせは打撃に合わせるため、叩いた拍とのずれが広がり、拍 F が少し下がる (0.970 → 0.953)。
どちらが「拍の位置」として正しいかは、波形の立ち上がりで付けた正解がないため決められなかった。ADTOF 自体も正解より 4〜7 ms 早く出る偏りがある (PoC 2)。

## 打撃の割り当て (SC-004) を測れなかった理由

叩いた拍は 1 拍ごとに約 23 ms (標準偏差) ばらつく。167 BPM では 16 分音符と 3 連符の境目が約 30 ms しか離れないため、叩いた正解ではグリッド位置の判定が叩いたブレに左右される (B・BLUE で不一致 161 打のうち 143 打が、拍ちょうどと 3/4、1/2 と 1/3・2/3 の取り違え)。
このため SC-004 は手で付けた正解で測ることにした (spec Clarifications) が、開発者が拍の手付けに自信がなく見送った。叩いた正解での 0.786 は、ブレで下がった下限の参考値。
小節と拍番号までの一致 (グリッド位置を除く) は、B・BLUE で 0.93 (1645 / 1768) だった。

## 評価の限界

- **正解**: 開発者 1 人が叩いた拍。叩いたタイミングのブレは推定との差から約 23 ms と見積もったが、手で付けた正解との比較はしていない。
- **ジャンル・拍子**: ロック 5 曲、すべて 4/4、167 / 187〜191 BPM。小節の頭の整理は 4/4 を前提にしている。
- **曲の入り**: 叩き始めがドラムの入りからの曲 (ONLY YOU 0:23 から) では、イントロ (推定がハーフテンポになった区間) を評価していない。

## 次のステップ

1. Human Review: 条件付き Go でよいか。`poc map` の既定を「整理後 + 位置合わせ」と「整理後のみ」のどちらにするか (叩いた正解との一致は位置合わせなしの方が良い)。
2. ユーザー演奏と Reference の比較 (次の PoC) で、グリッド位置の精度がどこまで必要かを決め、必要なら SC-004 を測る。
3. 推定が不安定な区間の扱い: 拍の活性値や整理での位相の切り替わりから、区間ごとの信頼度を出す。
