## Clarifications

### Session 2026-10-04

- Q: 拍の正解をどう用意するか → A: 2 つを併用する。(1) メイン: 原曲を流しながら電子ドラムで拍ごとにパッドを叩き (小節の頭は別のパッド)、曲全体の拍と小節の頭を記録する。(2) サブ: 1〜2 曲の 1〜2 区間で、波形を見ながら手で拍と小節の頭を付け、(1) の叩いたタイミングのブレを確かめる。曲の途中で小節の頭の推定がずれる問題を見逃さないよう、曲全体を正解にする。
- Q: 打撃の割り当て (SC-004) をどちらの正解で測るか (2026-10-04 のパイロット評価を受けて、開発者が承認) → A: 手で付けた正解で測る。叩いた拍は 1 拍ごとに約 23 ms ばらつき (標準偏差)、167 BPM では 16 分音符と 3 連符の境目が約 30 ms しか離れないため、叩いた正解ではグリッド位置の判定が叩いたブレに左右される (B・BLUE で一致率 0.871)。叩いた正解は拍・小節の頭・BPM・拍子 (SC-001〜SC-003、許容範囲 ±70 ms) に使う。手で付ける区間は 2〜3 曲 (167 BPM と 187 BPM を含む)・各 8 小節程度とする。

## User Scenarios & Testing *(mandatory)*

本 PoC の利用者は開発者 (ドラマー) 自身である。目的は「PoC 2 で取り出した打撃イベントを、曲の小節・拍の上に正しく並べられるか」を判断すること。
小節・拍の位置が分かって初めて、「苦手な小節の抽出」「指定区間のループ」「テンポを落とした練習」(Product Goal) が成り立つ。
完璧なドラム譜は目指さない (Constitution II)。拍のグリッドからのずれは記録するが、良し悪しは判定しない (Constitution VI)。

### User Story 1 - 曲の拍と小節の位置を推定する (Priority: P1)

開発者は PoC 1 の分離結果を 1 つ指定する。システムは原曲から拍 (beat) と小節の頭 (downbeat) の時刻を推定し、
BPM と拍子を求めて「拍のグリッド (BeatGrid)」として保存する。
あわせて、原曲に拍のクリック (小節の頭は高い音) を重ねた確認用の音声を出力し、開発者は耳で拍と小節の頭が合っているかを確かめられる。

**Why this priority**: 拍と小節の頭が分からなければ、打撃イベントを小節・拍に対応付けられない。

**Independent Test**: PoC 1 の分離結果 1 つを指定して実行し、BeatGrid と確認用の音声ができ、
原曲に重ねて聴くと拍のクリックが曲に合い、高い音が小節の頭で鳴ることを確認する。

**Acceptance Scenarios**:

1. **Given** PoC 1 の分離結果、
   **When** 開発者が拍の推定を実行する、
   **Then** 拍の時刻の一覧、小節の頭の時刻の一覧、BPM、拍子を持つ BeatGrid が保存される。
2. **Given** 推定で拍が取りこぼされた区間 (例: イントロでハーフテンポとして推定された部分)、
   **When** BeatGrid を作る、
   **Then** 前後の拍の間隔から取りこぼした拍が補われ、補った拍であることが分かる形で記録される。
3. **Given** 小節の頭の推定が途中で 1〜7 拍の不揃いな小節を作る曲、
   **When** BeatGrid を作る、
   **Then** 推定そのままの小節の頭と、拍子に合わせて整えた小節の頭の両方が記録され、どちらを使ったかが分かる。
4. **Given** BeatGrid、
   **When** 開発者が確認用の音声を再生する、
   **Then** 拍ごとのクリックと小節の頭の高いクリックを原曲に重ねて聴ける。

---

### User Story 2 - 打撃イベントを小節・拍に対応付ける (Priority: P1)

開発者は BeatGrid と PoC 2 の打撃イベントを組み合わせる。システムは各打撃イベントに、小節番号・拍番号・拍の中の位置
(例: 2 小節目の 3 拍目の裏) と、一番近いグリッド位置からのずれ (ms) を付けて、Reference Performance Data として保存する。

**Why this priority**: Reference Performance Data が、この後のユーザー演奏との比較・苦手箇所の抽出の土台になる。US1 と合わせて PoC 3 の最小構成。

**Independent Test**: 1 曲分の BeatGrid と打撃イベントから Reference Performance Data を作り、
任意の小節を指定すると、その小節の打撃イベントが拍の位置つきで一覧できることを確認する。

**Acceptance Scenarios**:

1. **Given** BeatGrid と PoC 2 の打撃イベント、
   **When** 対応付けを実行する、
   **Then** 各打撃イベントに小節番号・拍番号・拍の中の位置・グリッドからのずれ (ms) が付いた一覧が保存される。
2. **Given** 小節の頭の少し手前で叩かれた打撃 (例: 次の小節の 1 拍目より 20 ms 早い Kick)、
   **When** 対応付ける、
   **Then** その打撃は前の小節の最後ではなく、次の小節の 1 拍目に対応付けられ、ずれは負の値 (早い) として記録される。
3. **Given** 最初の小節の頭より前の打撃 (弱起・フィルイン)、
   **When** 対応付ける、
   **Then** 小節番号 0 として扱われ、捨てられない。
4. **Given** Reference Performance Data、
   **When** 開発者が小節番号の範囲を指定する、
   **Then** その範囲の打撃イベントだけを取り出せる (練習区間の切り出しの前提)。

### User Story 3 - 拍・小節の推定と対応付けの正しさを測る (Priority: P2)

開発者は評価セットの各曲で、拍と小節の頭の正解を用意する (電子ドラムで拍を叩いて曲全体を記録し、一部の区間は手でも付ける)。システムは推定した BeatGrid を正解と比べ、
拍と小節の頭の検出の正しさ・BPM の誤差・拍子の一致を出力する。
さらに、確認区間の打撃イベントが正しい小節・拍に割り当てられた割合を出力する。

**Why this priority**: Constitution I (Measurable PoC) に従い、PoC 3 の Go/No-Go を数値で判断するため。

**Independent Test**: 1 曲分の正解を用意して評価を実行し、拍・小節の頭の指標、BPM の誤差、拍子の一致、割り当ての正解率が出力されることを確認する。

**Acceptance Scenarios**:

1. **Given** 確認区間の拍と小節の頭の正解と、推定した BeatGrid、
   **When** 評価を実行する、
   **Then** 拍と小節の頭それぞれについて、正しく検出できた数・見逃し・余計な検出と F-measure (許容範囲 ±70 ms) が出力される。
5. **Given** 同じ区間の、電子ドラムで叩いた正解と手で付けた正解、
   **When** 両者を比べる、
   **Then** 叩いたタイミングのブレ (中央値・95 パーセンタイル, ms) が出力され、評価結果に併記される。
2. **Given** 正解の拍から求めた BPM と拍子、
   **When** 評価する、
   **Then** 推定 BPM の誤差 (%) と、拍子が一致したかが出力される。
3. **Given** 確認区間の打撃イベント、
   **When** 推定した BeatGrid と正解の BeatGrid のそれぞれで小節・拍に対応付ける、
   **Then** 両者で小節番号と拍の中の位置が一致した打撃の割合が出力される。
4. **Given** 複数曲の評価結果、
   **When** 集計する、
   **Then** 曲ごとと全体の指標を比較でき、Success Criteria の判定が出る。

### User Story 4 - 原曲と Drum Stem のどちらで拍を推定するのがよいか確かめる (Priority: P3)

開発者は同じ曲で、原曲を入力にした推定と Drum Stem を入力にした推定を同じ正解で比べる。

**Why this priority**: 計画では、ベースやコード進行が小節の頭の手がかりになるため原曲を基本にしている (docs/poc-plan.md §4)。
ドラムだけでも十分なら、将来ユーザーの演奏 (ドラムだけの音) にも同じ推定を使える。ただし PoC 3 の成否判断には US1〜US3 が先に必要。

**Independent Test**: 1 曲で 2 つの入力それぞれの指標が並べて出力されることを確認する。

**Acceptance Scenarios**:

1. **Given** 同じ曲の原曲と Drum Stem、
   **When** それぞれを入力に拍を推定して評価する、
   **Then** 同じ形式の指標が並べて出力される。

---

### Edge Cases

- イントロやブレイクのようにドラムや楽器が鳴らない区間でも、前後の拍の間隔が合う範囲で拍を補う。補えない長い無音区間は拍なしのまま残し、その区間の打撃イベントには小節・拍を付けずに理由を記録する。
- 推定した拍の位置は、原曲のドラムの打撃より一定量 (PoC 2 では 10〜20 ms) 遅れることがある。打撃イベントとの差の代表値でグリッド全体の位置を補正してよいが、補正量を記録する。
- 1 曲の中で小節の頭の推定が数拍ずれる区間がある (WORKING MAN の 1:06〜1:58 など)。拍子に合わせて整えた結果と推定そのままの結果を区別して記録する。
- 曲の途中でテンポが揺れる (生演奏、クリックなし) ことを前提とする。BPM は曲全体の代表値に加え、区間ごとの値も持つ。
- 拍子が途中で変わる曲 (例: 4/4 の中の 2/4 の小節) は、評価セットにあれば記録上で分かるようにする。拍子の変化を正しく扱うことは本 PoC の必須要件にしない。
- 3 連符・シャッフルのように拍を 3 つに分けるリズムがあっても、拍の中の位置は拍に対する割合で記録されるため情報は失われない。一番近いグリッド位置は 16 分音符と 3 連符の両方から選ぶ。
- 正解の対象区間外の推定・打撃イベントは評価に含めない。電子ドラムで叩いた正解は、最初と最後に叩いた拍の間を対象区間とする。
- 拍を叩いた正解には、叩き損ね (拍の抜け・二度打ち) が混ざりうる。前後の拍の間隔から明らかに外れた打撃は警告として記録し、開発者が確認できるようにする。
- BeatGrid と打撃イベントの元になった曲 (PoC 1 の実行) が一致しない場合は対応付けを拒否する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは PoC 1 の分離結果を入力として受け付け、原曲 (分離前の音声) から拍と小節の頭の時刻を推定しなければならない。入力を Drum Stem に切り替えて同じ推定ができなければならない (US4)。
- **FR-002**: システムは推定結果から BeatGrid (拍の時刻の一覧・小節の頭の時刻の一覧・BPM・拍子) を作らなければならない。BPM は曲全体の代表値と区間ごとの値、拍子は小節の頭の間の拍数から求める。
- **FR-003**: システムは推定で取りこぼされた拍を、前後の拍の間隔から補えなければならない。補った拍には印を付ける。
- **FR-004**: システムは小節の頭の推定を拍子に合わせて整えられなければならない。推定そのままの小節の頭と整えた小節の頭を両方記録し、対応付けにどちらを使ったかを記録する。
- **FR-005**: システムは BeatGrid の位置を原曲の打撃に合わせる補正を行えなければならない。補正量を記録し、補正なしの結果とも比べられること。
- **FR-006**: システムは原曲に拍のクリック (小節の頭は別の高さの音) を重ねた確認用の音声を出力しなければならない。
- **FR-007**: システムは BeatGrid と PoC 2 の打撃イベントから、各打撃イベントに小節番号・拍番号・拍の中の位置 (拍に対する割合)・一番近いグリッド位置 (16 分音符または 3 連符)・そこからのずれ (ms、負は早い) を付けた Reference Performance Data を作らなければならない。
- **FR-008**: 対応付けでは、打撃は最も近い拍を基準にし、小節の頭の直前の打撃を前の小節の最後に割り当ててはならない (US2 シナリオ 2)。最初の小節の頭より前の打撃は小節番号 0 とする。
- **FR-009**: Reference Performance Data から、小節番号の範囲を指定して打撃イベントを取り出せなければならない。
- **FR-010**: BeatGrid と Reference Performance Data は、ML モデル固有の形式ではなく、プロジェクトの Domain Model (BeatGrid / ReferencePerformance / DrumEvent) の形で保存しなければならない (Constitution III)。
- **FR-011**: システムは拍と小節の頭の正解を、次の 2 つの方法で用意して読み込めなければならない。
  (1) メイン: 開発者が原曲を聴きながら電子ドラムで拍ごとにパッドを叩き (小節の頭は別のパッド)、曲全体の拍と小節の頭を記録する。PoC 2 のキャリブレーションで測ったずれで時刻を補正する。
  (2) サブ: 1〜2 曲の 1〜2 区間 (各 8 小節程度) で、開発者が波形を見ながら拍と小節の頭を手で付ける。(1) の叩いたタイミングのブレを見積もるために使い、そのブレを評価結果に併記する。
- **FR-012**: 評価は拍と小節の頭それぞれについて、正解と推定を許容範囲 (初期値 ±70 ms、変更可能) 内で 1 対 1 に対応付け、正しく検出できた数・見逃し・余計な検出・F-measure を出力しなければならない。
- **FR-013**: 評価は推定 BPM の誤差 (%) と拍子の一致を出力しなければならない。
- **FR-014**: 評価は確認区間の打撃イベントについて、推定した BeatGrid と正解の BeatGrid での小節番号・拍の中の位置 (一番近いグリッド位置) の一致率を出力しなければならない。
- **FR-015**: システムは実行ごとに、入力 (PoC 1 の実行・打撃イベントの抽出の実行・曲の識別情報)、推定方式とバージョン、設定値、補正の内容、処理時間、最大メモリ、警告を記録しなければならない。
- **FR-016**: 拍の推定方式は、記録・評価の仕組みを変えずに別の方式へ差し替えられなければならない。
- **FR-017**: 複数曲の評価結果を曲ごと・全体で集計し、Success Criteria の判定を出力しなければならない。
- **FR-018**: 楽曲データ・推定結果・正解データをリポジトリに含めず、外部へ送信してはならない (Constitution IV)。

### Key Entities

- **BeatGrid (拍のグリッド)**: 拍の時刻の一覧 (補った拍の印つき)、小節の頭の時刻の一覧 (推定そのまま・整えたもの)、BPM (曲全体・区間ごと)、拍子、位置の補正量。元になった PoC 1 の実行と入力 (原曲 / Drum Stem)。
- **Beat Position (拍の位置)**: 小節番号・拍番号・拍の中の位置 (割合)・一番近いグリッド位置 (16 分音符 / 3 連符)・そこからのずれ (ms)。
- **ReferencePerformance (練習用の参照データ)**: BeatGrid と、拍の位置が付いた DrumEvent の一覧。元になった打撃イベントの抽出の実行。
- **Beat Ground Truth (拍の正解)**: 作り方 (電子ドラムで叩いた / 手で付けた)、対象の区間 (叩いた場合は曲全体)、拍の時刻と、どれが小節の頭か。元になった PoC 1 の実行。叩いた場合は使ったキャリブレーションも記録する。
- **Beat Evaluation (評価結果)**: BeatGrid と正解の組に対する、拍・小節の頭の指標、BPM の誤差、拍子の一致、打撃の割り当ての一致率。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 評価セット全体で、拍の F-measure が 0.95 以上。
- **SC-002**: 評価セット全体で、小節の頭の F-measure が 0.90 以上。
- **SC-003**: 推定 BPM (曲全体の代表値) の誤差が全曲で 2% 以内。拍子が全曲で一致する。
- **SC-004**: 手で拍を付けた区間の打撃イベントのうち 95% 以上が、正解の BeatGrid と同じ小節・拍・グリッド位置に割り当てられる。
- **SC-005**: 評価セットの 5 曲すべてで、曲全体の拍と小節の頭の正解 (電子ドラム) を用意して評価が完了し、さらに 2〜3 曲 (167 BPM と 187 BPM を含む) の区間で手で拍を付けて評価が完了し、手で付けた正解と比べた叩いた正解のブレ (中央値) が 20 ms 以内である。
- **SC-006**: 4 分の曲 1 曲の拍の推定と対応付けが、開発者の MacBook Air (Apple M1, 16GB) で 2 分以内に完了する (PoC 1・PoC 2 の処理時間は含まない)。
- **SC-007**: 同じ入力・同じ設定で再実行すると、同じ BeatGrid と Reference Performance Data が得られる。
- **SC-008**: すべての実行で FR-015 の項目が欠けなく記録されている。
- **SC-009**: 1 曲分の拍の正解 (電子ドラムで叩く) を用意する作業が、開発者の作業 15 分以内で終わる。

## Assumptions

- 利用者は開発者 1 名。操作は手元の Mac で行い、画面 UI は不要 (正解を付ける作業を除く)。
- 入力は PoC 1 の分離結果と PoC 2 の打撃イベント (HiHat の閾値 0.12 の設定) を使う。
- 評価セットは PoC 2 と同じロック 5 曲 (NO. NEW YORK / B・BLUE / ONLY YOU / WORKING MAN / PLASTIC BOMB)。BPM は 167 または 187.5 付近で、すべて 4/4 拍子と想定する。ほかのジャンル・拍子・テンポは本 PoC では確認しない。
- 拍の推定には PoC 2 で録音用クリックに導入済みの推定方式を使う (docs/poc-plan.md §3.3 で選定・承認済み)。PoC 2 で次のことが分かっている。
  - BPM は 5 曲とも正しく出る。
  - 小節の頭の推定が曲によって乱れる (PLASTIC BOMB は 1〜7 拍の小節が多い、WORKING MAN の 1:06〜1:58 は 2 拍ずれ、ONLY YOU のイントロはハーフテンポで拍を取りこぼす)。
  - 拍の位置は原曲のドラムより 10〜20 ms 遅れる。
  - 録音用クリックで使った、取りこぼした拍の補い方とドラムへの位置合わせは、本 PoC の FR-003・FR-005 の出発点にする。
- 打撃イベントの拍の中の位置は、ユーザー演奏との比較で使う。演奏者の評価 (ユーザー演奏と Reference の比較) と練習メニューの生成は本 PoC の範囲外。
- 小節の頭を整える (FR-004) ときは、評価セットがすべて 4/4 であることを使ってよい。拍子の変化への対応は範囲外。
- 楽曲・推定結果・正解データはローカルにだけ置く (`data/`・`output/`、Git 管理外)。
