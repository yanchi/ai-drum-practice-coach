# Research: Beat / Downbeat Analysis and Bar Mapping (PoC 3)

PoC 3 の実装判断。技術選定 (Beat This!) は [docs/poc-plan.md](../../docs/poc-plan.md) §3.3 で承認済みで、PoC 2 で録音用クリックのために導入済み (`beat-this` 1.1.0, PoC 2 research R-18)。
新しい依存は追加しない。

## R-01: 拍の推定の入力と出力

- **Decision**: Beat This! (`final0`, CPU) に、PoC 1 の入力曲 (原曲) を `poc/audio/decode.py` でデコードしたものを渡す (US4 では `drums.wav`)。
  推定そのもの (`Audio2Frames`) の出力のうち、拍と小節の頭の活性値 (フレームごと、50 fps) と、既定の後処理 (`minimal`) で得た拍・小節の頭の時刻の両方を受け取る。
  活性値は R-03 の小節の頭の整理に使う。Beat This! の型は `poc/beat/beat_this_adapter.py` の中だけで扱う (Constitution III)。
- **Rationale**: PoC 2 のクリックは `drums.wav + accompaniment.wav` を入力にしたが、計画どおり原曲を基本にする。PoC 1 で原曲と Drum Stem の時間軸のずれは 0 サンプルと確認済みのため、ADTOF の打撃イベントと同じ時間軸になる。
  小節の頭は時刻だけだと「有る / 無い」しか分からず、乱れた区間を直す手がかりにならない。活性値があれば各拍の「小節の頭らしさ」を比べられる。
- **Alternatives considered**: DBN 後処理 (`dbn=True`) は madmom が必要で、現行 Python で入らない (poc-plan §3.3)。採らない。
  小さいモデル `small0` (8 MB) はモバイル向けの候補だが、PoC 3 では精度の確認を優先して `final0` を使う。

## R-02: 取りこぼした拍の補い (FR-003)

- **Decision**: PoC 2 の `fill_beat_gaps` (拍の間隔の中央値の整数倍 ±15% の隙間に、1〜3 拍を等間隔で補う) を BeatGrid 作成の最初の段に使う。補った拍には `inferred: true` を付ける。
  間隔の中央値は曲全体ではなく、前後 16 拍の中央値にする (テンポの揺れに追従するため)。4 拍より長い隙間は補わない。
- **Rationale**: PoC 2 で、ONLY YOU のイントロ (ハーフテンポ) で 46 拍、PLASTIC BOMB で 73 拍を補い、クリックが曲に合うことを耳で確認した。
- **Alternatives considered**: 活性値の弱い山を拾い直す方法は、閾値の調整が増える。補えなかった場合の比較材料として残す。

## R-03: 小節の頭の整理 (FR-004)

- **Decision**: 評価セットがすべて 4/4 であることを使い、拍ごとに「小節の何拍目か」(位相 0〜3) を Viterbi で決める。
  - 観測: 各拍の小節の頭の活性値 (R-01)。
  - 遷移: 位相は 1 拍ごとに 1 進むのが基本。位相の飛び (2/4 の小節やフィルの取り違え) は大きなペナルティ付きで許す。
  - 出力: 位相 0 の拍を小節の頭とする。推定そのままの小節の頭 (`downbeats_raw`) と並べて保存する。
  - 拍子 (FR-002) は、推定そのままの小節の頭の間の拍数の最頻値で決める。整理は拍子が 4 のときだけ行い、それ以外は推定そのままを使って警告を出す。
- **Rationale**: PoC 2 で見た乱れは「位相が 2 拍ずれた区間が続く」(WORKING MAN) と「1 拍だけの小節が散発する」(PLASTIC BOMB) だった。どちらも、局所的な判定を前後の小節の一貫性で抑えれば直る。
  位相の状態は 4 つだけなので計算も実装も小さい。
- **Alternatives considered**:
  - 曲全体で位相を 1 つに固定: 位相の多数決は B・BLUE / WORKING MAN で 80%、NO. NEW YORK で 51%、PLASTIC BOMB で 43% しか一致しなかった (PoC 2 の調査)。途中で本当に位相が変わる (2/4 の小節が入る) 曲で破綻する。
  - スネアのバックビート (2・4 拍目) を手がかりにする: ドラム固有の知識で、効果は大きそうだが、フィル・キメで外れる。整理の後で効果を比べる候補として残す (R-03 の観測に足すだけで試せる)。

## R-04: グリッドの位置合わせ (FR-005)

- **Decision**: PoC 2 の `drum_offset_sec` (ADTOF の Kick / Snare の時刻 − 最も近い拍、±60 ms 以内の中央値) で BeatGrid 全体をずらす。補正量 (ms) を記録し、`--no-offset` で補正なしも作れるようにする。
- **Rationale**: Beat This! の拍は 20 ms 刻みで、原曲のドラムより 10〜20 ms 遅れた (PoC 2)。打撃イベントを拍に対応付けるとき、この遅れがそのまま「全部の打撃が早い」というずれに見える。
- **Alternatives considered**: 活性値の山を補間して 20 ms より細かく位置を出す方法は、遅れの原因 (山の位置そのもの) を直さない。

## R-05: 打撃イベントの小節・拍への対応付け (FR-007, FR-008)

- **Decision**:
  1. 各打撃の時刻 t について、t を挟む拍 b_i ≤ t < b_{i+1} から、連続した拍の位置 `x = i + (t − b_i) / (b_{i+1} − b_i)` を求める。
  2. x の小数部分を、16 分音符 (0, 1/4, 1/2, 3/4) と 8 分の 3 連符 (1/3, 2/3) の中で一番近いグリッド位置に丸める。丸めた結果が 1 なら次の拍の 0 にする (小節の頭の直前の打撃は次の小節の 1 拍目になる)。
  3. 丸めたグリッド位置の時刻との差を「ずれ (ms)」とする (負は早い)。
  4. 小節番号は、丸めた拍より前にある小節の頭の数。最初の小節の頭より前は 0。拍番号は、その小節の頭から数えた拍の番号 (1 始まり)。
  5. 前後の拍の間隔が 1.5 倍以上離れた (拍がない) 区間の打撃は、小節・拍を付けずに理由を記録する。
- **Rationale**: 拍の間隔ごとに割合を出すので、テンポの揺れに追従する。グリッド位置は情報を捨てずに記録し、丸めはユーザー演奏との比較のための補助にとどめる (Constitution VI)。
- **Alternatives considered**: 時刻だけで最も近いグリッド点を探す方法は、拍の間隔が揺れると 3 連符と 16 分音符の境目で不安定になる。

## R-06: 拍の正解 — 電子ドラムで叩く (FR-011 (1))

- **Decision**: `poc record <run> --tap-beats` を追加する。PoC 2 の録音の仕組み (duplex ストリーム、MIDI の時刻合わせ、キャリブレーション) をそのまま使い、再生するのは**伴奏ではなく原曲**。クリックは鳴らさない (推定した拍を正解に写してしまうため)。
  開発者は拍ごとにハイハット (手でもペダルでもよい) を踏む / 叩き、小節の頭では同時にキックも踏む。
  - 拍 = ハイハットのノート、小節の頭 = キックのノートから ±50 ms 以内にあるハイハットの拍。
  - 時刻はキャリブレーションのパッドごとのずれで補正する (PoC 2 R-06)。ドラムの音声は使わない (MIDI だけ)。
  - 叩き損ねの検出: 前後 8 拍の間隔の中央値から 35% 以上外れた間隔を警告として記録する。正解の修正は手で行う (自動では直さない)。
- **Rationale**: 曲全体の拍と小節の頭を、曲の長さと同じ時間で取れる。PoC 2 で測った叩くタイミングのばらつき (std 約 20 ms) は、評価の許容範囲 ±70 ms より十分小さい。
- **Alternatives considered**: 演奏そのもの (PoC 2 の録音) から拍を作る方法は、演奏に拍が抜ける区間 (ブレイク) があり、小節の頭も分からない。

## R-07: 拍の正解 — 手で付ける (FR-011 (2))

- **Decision**: PoC 2 の `poc annotate` に `--beats` を追加する。ページに「拍」のレーン (全体の波形) を出し、クリックで拍、Shift+クリックで小節の頭を付ける。印は音の立ち上がりの始まりに合う (PoC 2 R-21)。
  保存先は `data/annotations/<名前>/beats.csv` (`time_sec,label`、ラベルは `b` / `d`)。区間は同じ `annotation.yaml` の `beat_regions` に書く (打撃の区間とは別)。
  比較は、手で付けた拍と叩いた拍を ±70 ms で 1 対 1 に対応付け、差の中央値と 95 パーセンタイルを出す (SC-005)。
- **Rationale**: 既存のツールを拡張すれば、操作に慣れた画面で付けられる。
- **Alternatives considered**: 別のページを作る方法は、ほぼ同じコードの重複になる。

## R-08: 評価の指標 (FR-012〜FR-014)

- **Decision**:
  - 拍・小節の頭の F-measure: 正解と推定を ±70 ms で 1 対 1 に対応付け (PoC 2 の `_assign` を使う)、P / R / F を出す。評価は正解の対象区間 (叩いた最初と最後の拍の間) の中だけ。
  - BPM: 正解の拍の間隔の中央値から求めた BPM と、推定の曲全体の BPM の差 (%)。
  - 拍子: 正解の小節の頭の間の拍数の最頻値と、推定の拍子の一致。
  - 打撃の割り当て: 確認区間の打撃イベント (ADTOF) を、推定の BeatGrid と正解の BeatGrid のそれぞれで対応付け、(a) 属する小節の頭が ±70 ms で同じ時刻、(b) 小節内の拍番号が同じ、(c) グリッド位置が同じ、の 3 つがそろった割合。小節番号そのものは比べない (最初の小節の数え方の違いで全部ずれるのを避ける)。
  - 推定そのまま・整理後・位置合わせなしの 3 通りの BeatGrid を同じ正解で評価し、整理と位置合わせの効果を並べる。
- **Rationale**: 拍の評価の標準的な許容範囲 (±70 ms) を poc-plan §7.3 のとおり使う。外部の評価ライブラリ (mir_eval) は使わず、PoC 2 の対応付けを再利用する (依存を増やさない)。
- **Alternatives considered**: 小節番号の一致率は、正解の 1 小節目の取り方 (イントロの扱い) に左右されるため採らない。

## R-09: 確認用の音声 (FR-006)

- **Decision**: PoC 2 の `add_beat_clicks` (小節の頭 1600 Hz・ほかの拍 1000 Hz) で、原曲 (−6 dB) にクリックを重ねた `check.wav` を出す。補った拍は同じ音で鳴らす。
- **Rationale**: PoC 2 で開発者が聴いて確認できた形式。

## R-10: 再現性と記録 (FR-015, SC-007, SC-008)

- **Decision**: `beatgrid.json` / `reference.json` / 評価結果に、入力のハッシュ、Beat This! のバージョンとチェックポイント、整理・補い・位置合わせの設定と結果、処理時間、最大メモリ、環境を記録する (PoC 1・2 と同じ項目)。
  再現性は、同じ入力で 2 回実行して拍の時刻が完全に一致することで確認する (`poc check-beats`)。
- **Rationale**: Beat This! の推定は CPU で決定的と想定する。一致しない場合は差の最大値を記録して Human Review で扱う。

## R-11: 処理時間 (SC-006)

- **Decision**: 測定のみ。PoC 2 のクリック作成では、4 分の曲の Beat This! (CPU) が約 6 秒 (重みのダウンロード後) だった。整理 (Viterbi、4 状態 × 約 700 拍) と対応付けは数秒以内と見込む。
